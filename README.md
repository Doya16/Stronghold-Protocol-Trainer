# Stronghold Protocol Trainer｜明日方舟-卫戍协议 本地修改器

**想试一套成型阵容，又不想反复刷商店？** 给 [卫戍协议：盟约 / Stronghold Protocol](https://github.com/sganggs/Stronghold-Protocol) 加一个本地修改面板：设置金币、调整盟约层数，点击图标获得物品和本局可用干员。

[下载安装包](https://github.com/Doya16/Stronghold-Protocol-Trainer/releases/latest) · [图文安装教程](#install) · [功能实机展示](#features) · [网上阵容参考](#community) · [反馈问题](https://github.com/Doya16/Stronghold-Protocol-Trainer/issues)

**v0.4.0：适配本体 v0.3.0。** 支持新版可扩展暂存队列，面板显示暂存总数和排队数量；素材索引缓存纳入退出清理，同时修复小窗口中修改器遮挡大厅 / 自选确认按钮的问题。大厅、开局确认与策略选择时暂时隐藏入口，进入战场后恢复；服务断开会禁用按钮并提示重新连接。

**支持本体 v0.3.0 / v0.2.5 / v0.1.3。** 金币、盟约、物品、已配置且未被禁用的自选干员均按本局数据处理。其他本体版本尚未验证，不会自动放行。

**插件范围：** v0.3.0 启用玩法插件的房间使用独立对局进程，当前 Trainer 暂不支持修改此类房间，会显示明确提示。请新建未启用玩法插件的房间使用修改器。安装的插件文件属于用户内容，不作为缓存删除。

**升级步骤：** 先关闭游戏，备份旧本体目录，按本体 README 升级到 v0.3.0（不确定增量包适用范围时使用完整包）。随后解压新版 Trainer ZIP，运行安装器，选择新的本体根目录，点击“安装 / 启用”。本体与 Trainer 版本号各自独立；安装 Trainer 不会替你更新本体。

![终极模拟第 3 回合：多个盟约 999 层，场上阵容与整备区全景](docs/trainer-showcase.png)

*Doya16 提供的实机截图：终极模拟第 3 回合，拉特兰、精准、奇迹、远见等盟约显示 999 层，场上与整备区的干员一览。*

**非官方同人扩展，仅供本地测试及个人非商业娱乐。禁止利用游戏素材盈利。** 游戏素材版权归鹰角网络 / Yostar 及相应权利人；本项目不包含本体和素材包，声明见 [NOTICE.md](NOTICE.md)。

## 图文安装教程

### 第 1 步：准备本体和修改器

| 需要准备 | 下载 / 检查方式 |
| --- | --- |
| Windows x64 | 当前图形安装器支持的系统 |
| 本体 **v0.3.0 完整包** | [本体 v0.3.0 发布页](https://github.com/sganggs/Stronghold-Protocol/releases/tag/v0.3.0)，下载 `Stronghold-Protocol-v0.3.0.zip`；已有 v0.2.5 / v0.1.3 也可使用 |
| Node.js **22 或 24** | [Node.js 官方下载](https://nodejs.org/zh-cn/download)；本体目录已有 `runtime/node.exe` 且版本符合要求时也可使用 |
| Chrome 或 Edge | 用于启动独立游戏窗口 |
| 修改器安装包 | [修改器 Releases](https://github.com/Doya16/Stronghold-Protocol-Trainer/releases/latest)，下载 `Stronghold-Protocol-Trainer-v0.4.0-win-x64.zip` |

打开修改器发布页，找到页面下方 **Assets**，选择名称以 **`win-x64.zip`** 结尾的附件。`Source code (zip)` 和 `Source code (tar.gz)` 是开发用源码，不是可以双击安装的成品。

安装步骤配图保留 v0.2.0 时拍摄的界面，操作相同；版本号与下载文件名以本页文字为准。

### 第 2 步：完整解压，确认本体能运行

把两个 ZIP 分别完整解压到普通文件夹；不要直接在压缩包预览里运行 EXE。建议使用短路径、可写目录，例如 `D:\Games\Stronghold-Protocol`，避免放在 OneDrive 同步目录中。

先阅读**本体自己的 `README.md` → 快速开始 → 整合包**，完成 Node.js 环境准备，并通过本体的 `scripts\start-windows.bat` 确认原版能打开。完整包已包含本体依赖与素材；修改器不会替你补下载这些内容。

**安装器要选择的是包含 `package.json` 的那一层。** 如果解压后套了两层同名文件夹，请继续进入内层。

```text
D:\Games\Stronghold-Protocol\       ← 安装器应填写这一层
├─ package.json
├─ README.md
├─ server\
├─ public\
├─ data\
├─ node_modules\
└─ scripts\

D:\Downloads\Stronghold-Protocol-Trainer-v0.4.0-win-x64\
└─ Stronghold-Protocol-Trainer-Setup.exe   ← 双击这个安装器
```

### 第 3 步：选目录，安装 / 启用

1. 关闭之前用于检查的游戏和服务窗口。
2. 双击 **`Stronghold-Protocol-Trainer-Setup.exe`**。
3. 粘贴本体根目录，或点 **浏览…** 选择它。下图路径是示例，请换成你自己的实际路径。
4. 点击 **安装 / 启用**，等待下方状态区提示成功，再点击 **启动游戏**。

![安装器已填写本体根目录，下方依次为安装启用、启动游戏、停用和卸载](docs/step-03-installer.png)

安装成功后，本体目录中会新增：

```text
sp-local-tools\                         ← 修改器文件
卫戍协议本地修改器 - 启动.lnk            ← 以后双击它进入
卫戍协议本地修改器 - 关闭并清理.lnk      ← 手动结束本次游戏并清理
```

无需管理员权限，但目录必须可写。安装器会检查本体版本、Node.js、浏览器和必要文件；提示缺失时，按提示补齐后重新安装即可。

### 第 4 步：从修改器入口打开游戏

第一次可直接点安装器的 **启动游戏**；以后双击本体目录里的 **卫戍协议本地修改器 - 启动** 快捷方式。

看到下图登录页后，输入博士代号，点击 **开始**。页面右下角出现“修改面板”，说明这次加载了扩展。

![启动成功：输入博士代号，右下角可见修改面板入口](docs/step-04-login.jpg)

### 第 5 步：开局，进入休整期

初次体验可以选择 **独立模拟 → 标准模拟 → 开始独立模拟**。然后依次点击 **开始模拟 → 准备就绪 → 确认选择**，等画面顶部进入“休息一下”。

![选择独立模拟与标准难度，点击开始独立模拟](docs/step-05-solo.jpg)

也可以使用同盟模拟添加 AI 队友。**本修改器入口仅监听本机 `127.0.0.1`**；本体的远程 / 局域网多人功能不等于本修改器提供远程修改能力。

### 第 6 步：打开面板并确认修改对象

点击右下角 **修改面板**，或按 **Ctrl + Shift + M**。确认上方状态为“第 … 回合 · 休整期”，并在“修改对象”中选中自己或目标 AI，再使用下面三个页签。

| 页签 | 最快上手方式 | 成功后看哪里 |
| --- | --- | --- |
| 数值 | 填写金币 → 设置金币；选择盟约 → 设为 999 层 | 面板底部成功提示、游戏资金和盟约栏 |
| 物品 | 筛选类型 / 阶位 → 点击物品图标 | 成功提示、整备区或暂存区 |
| 干员 | 搜索名字 → 点击干员头像 | 成功提示、整备区；已凑齐时会自动精锐化 |

准备就绪、战斗中或玩家已淘汰时不能修改。先取消准备，或等待下一轮休整期。

## 功能实机展示

页首及本节的四张实机截图均由 **Doya16** 提供，保留原始画面。分别展示阵容全景、金币与盟约层数、物品发放、干员列表及整备区状态；点击图片可查看原图。

### 金币与盟约：99999 金币、多个 999 层盟约

在“数值”页输入目标金额，点 **设置金币**；也可使用 **+100 金币 / +1000 金币**。资金会同步到游戏界面，之后购买、刷新和回合收入继续按原规则结算。

选择盟约后点击 **设为 999 层**。下图中，面板显示当前 **99999 金币**，底部成功提示为“金币 14006 → 99999”；游戏顶部的多个盟约也显示 **999 层**。

![数值面板显示 99999 金币与设置成功提示，游戏盟约栏显示多个 999 层](docs/trainer-values.png)

**层数和激活条件是两回事。** 设置 999 层不会自动把阵容补齐，也不会补发过去逐层叠加的奖励。请先让对应盟约达到激活条件，再看实际效果。

图中选中的“炎”就是 **999 层但未激活** 的示例；顶部亮起的盟约与灰色盟约仍按实际阵容判断激活状态。

### 物品：点击图标获得一件

切到“物品”，按名称、ID 或描述搜索，或使用**阶位 + 普通装备 / 强化装备 / 道具**筛选。下图展示高阶物品及强化装备图标，整备区已放入多件装备，面板底部可查看发放成功提示。

![物品页的高阶装备和强化物品列表，以及整备区中的装备](docs/trainer-items.png)

本体 v0.1.3 的列表共 115 项物品。每次点击发放一件，不扣金币；获得效果和自动合成仍由本体处理。装备拿到后仍要按游戏方式配发给干员，道具也要满足其使用条件。

**本体 v0.2.5 / v0.3.0 的装备库存限制仍然生效。** 库存由全队持有量计算，普通装备与强化装备都占用库存；不足时面板会明确提示“共享库存不足”，本次不发放。免费获得不等于无限库存。

### 干员：只显示本局未被 ban 的可获得干员

切到“干员”，搜索名字或筛选阶位，点击头像即可获得一名初始干员，不受当前商店等级限制。下图展示高阶干员列表，以及获得干员后场上、整备区和临时整备区的状态。

![高阶干员列表、精锐化提示及整备区已满时的容量提醒](docs/trainer-operators.png)

凑齐同名干员会按本体规则自动精锐化，可能出现晋升奖励。列表不直接发放精锐形态、召唤物或隐藏干员。获得后请自行从整备区拖到战场并选择朝向。

**支持本体 v0.2.5 / v0.3.0 的自选编队。** 开局前先在本体中配置自选干员（例如克莱门莎）；进入休整期后，该玩家本局已选且未被禁用的干员会以“自选干员”显示。切换修改对象时列表也随之切换；未配置的槽位和其他玩家的自选不会混入，修改编队后需要新开一局才会生效。

这张历史截图中的“暂存区已满”适用于旧本体。**本体 v0.3.0 的 5 个可见暂存格是队列窗口**，满后仍可继续获得，面板显示总数和排队数；腾出位置后本体自动补入。暂存内容仍会阻止准备就绪，并按本体规则在休整期截止时处理，建议及时部署、合成、使用或清理。

## 游戏规则与边界

- 每次图标点击发放一件，优先进入整备区，满时进入暂存区。本体 v0.1.3 / v0.2.5 两处全满且无法合成时会拒绝；v0.3.0 则进入可扩展暂存队列。
- 已有同类物品或干员可能立即自动合成，所以格子数量不一定增加；暂存区仍遵循本体清理规则。
- 干员共享卡池、自选干员个人库存与本体获得 / 合成流程保持一致；库存耗尽时仍按对应本体版本的赠送计数规则处理。
- 本体 v0.2.5 / v0.3.0 的物品共享库存不足时拒绝发放；这与整备区格子是否已满是两个独立限制。
- 禁用盟约不能设置层数；干员列表随对局重新过滤。换局或换回合后，旧请求会被拒绝。
- 修改只属于当前局。**关闭专用游戏窗口会结束本次服务并清理临时浏览器数据，不保留当前局存档。**

## 关闭、更新、停用与卸载

| 你想做什么 | 操作 | 结果 |
| --- | --- | --- |
| 正常退出 | 关闭专用游戏窗口 | 结束本次服务和浏览器进程，清理临时目录 |
| 手动结束并清理 | 双击“卫戍协议本地修改器 - 关闭并清理” | 清理本扩展管理的本次会话 |
| 更新修改器 | 先关闭游戏，新版安装器选择同一本体目录 → 安装 / 启用 | 更新独立扩展文件；运行中会阻止覆盖 |
| 暂时不用 | 安装器选择原目录 → 停用 | 禁止修改器入口启动；再次安装 / 启用即可恢复 |
| 删除扩展 | 安装器选择原目录 → 卸载扩展 | 移除扩展目录及属于扩展的两枚快捷方式，保留本体 |

扩展存放在 `sp-local-tools` 中，不修改本体源文件。原本体的启动脚本仍可使用；请区分它和修改器专用入口。

清理范围为 `sp-local-tools/runtime-data` 中本次浏览器配置、缓存、素材哈希索引和临时文件，以及扩展管理的进程。强制断电等异常退出的残留会在下次启动时清理；Windows 自身日志、系统预取等操作系统记录不在清理范围内。卸载时发现扩展目录里有用户额外文件，会保留并提示先移出。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 双击源码包找不到 EXE | 返回 Releases，下载 `win-x64.zip` 成品安装包 |
| 安装器说目录不正确 | 选择有 `package.json`、`server`、`public` 的本体根目录，检查是否多套了一层文件夹 |
| 提示本体版本不兼容 | v0.4.0 支持本体 v0.1.3 / v0.2.5 / v0.3.0；旧修改器请先更新，不要只改本体版本号绕过检查 |
| 没有修改面板 | 从“卫戍协议本地修改器 - 启动”进入；原版脚本不加载扩展 |
| 有按钮但不能修改 | 先确认对象、休整期、存活且未准备；读面板底部提示，再点“刷新” |
| 提示“对局已变化” | 换局或回合已切换，刷新面板后重新操作 |
| 改成 999 层但未激活 | 层数不会补齐阵容，请部署足够的对应盟约成员 |
| 点图标后看不到新卡 | 检查整备区、暂存队列及自动合成结果；v0.3.0 可见暂存格超过 5 件后会排队 |
| 格子有空位却提示库存不足 | 本体 v0.2.5 / v0.3.0 另有全队装备库存限制，普通与强化装备均占用库存 |
| 搜不到某名干员 | 确认筛选条件和本局 ban 位；召唤物、隐藏与精锐形态不会直接列出 |
| 搜不到克莱门莎等自选干员 | 使用本体 v0.2.5 / v0.3.0，在开局前配置自选编队；确认目标玩家和本局禁用情况 |
| 图片空白或变成文字 | 确认使用带素材的本体完整包；缺图时仍可按名称点击 |
| 下一轮金币变化了 | 本体的收入结算仍然生效，在新休整期重新设置即可 |
| 重开游戏找不到上一局 | 这是专用入口的临时会话设计，退出时会结束对局并清理 |

反馈时请附：本体 / 修改器版本、进行到哪一步、面板底部完整提示、相关截图。可在 [Issues](https://github.com/Doya16/Stronghold-Protocol-Trainer/issues) 提交。

## 开发与测试

扩展无额外 npm 依赖，通过 `SP_GAME_ROOT` 指定外部本体目录。本体应已安装自己的依赖，并包含上游 `test/` 目录。

```powershell
$env:SP_GAME_ROOT = 'D:\Games\Stronghold-Protocol'
node --test test/local-tools.test.mjs test/live-match.test.mjs
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
pwsh -File scripts/test-installer.ps1 -GameRoot $env:SP_GAME_ROOT
```

构建需要 Windows 自带 .NET Framework 4.x 编译器，生成安装器至 `dist/`。`Setup.Console.exe` 与图形安装器使用相同安装逻辑，供自动化验收；普通玩家无需使用。`scripts/release.ps1` 生成含文档的 ZIP 和 SHA256 校验文件。

v0.4.0 本地验收：本体 v0.3.0 通过 16 项自动化测试（跳过 1 项旧版容量测试）；v0.2.5 通过 15 项、v0.1.3 通过 12 项，其余版本专属项目按预期跳过。覆盖真实 WebSocket 开局、金币消费、盟约同步、物品与自选干员发放、合成、禁用与库存校验、新版暂存排队和玩法插件房间提示。CI 覆盖三种本体 × Node.js 22 / 24 及 Windows 构建，结果见 [Actions](https://github.com/Doya16/Stronghold-Protocol-Trainer/actions)。

另已验证 Windows 安装与覆盖更新、重复启动、运行中拒绝重装，以及“关闭并清理”后进程退出、端口释放、浏览器临时目录与素材索引删除。真实游戏页面的按钮操作与测试边界见 [测试记录](docs/TESTING.md)。
